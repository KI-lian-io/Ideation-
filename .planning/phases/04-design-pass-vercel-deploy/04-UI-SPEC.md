# Phase 04 — UI Design Contract

> Visual and interaction contract for Phase 4: Design Pass + Vercel Deploy.
> Generated by gsd-ui-researcher. Pending verification by gsd-ui-checker.

**Scope:** This contract governs (1) the new marketing landing page at `/`, (2) the full brand-identity upgrade applied to the existing tool UI at `/app`, and (3) the `layout.tsx`/`globals.css` cleanup. It EXTENDS the Phase 1 and Phase 2 contracts — any value not re-declared here is inherited verbatim from `01-UI-SPEC.md` and `02-UI-SPEC.md`. Executors must read all three; this file wins on any conflict.

**Source of all decisions:** `04-CONTEXT.md` D-01..D-23 are LOCKED. This spec translates those decisions into an executable contract. Nothing here was derived from user questions — all 23 decisions were pre-populated upstream.

## Design System

| Property | Value | Source |
|----------|-------|--------|
| Tool | none — hand-rolled Tailwind v4 only | Locked — `CLAUDE.md` "What NOT to Add" + no `components.json` |
| Preset | not applicable | — |
| Component library | none — no Radix, no shadcn, no headless UI | Locked — never add |
| Icon library | none — inline SVG only (existing lock icon in `page.tsx`; new icons in landing as inline SVG) | Locked — CLAUDE.md |
| Body/UI font | Geist Sans — variable `--font-geist-sans` via `next/font/google` | Inherited from Phase 1 |
| Mono font | Geist Mono — variable `--font-geist-mono` — date fields only | Inherited from Phase 1 |
| Serif font (NEW) | **Lora** — variable `--font-lora`, subsets: `latin`, display: `swap` — hero headline + section titles on landing only. Add via `next/font/google`. | D-11 — "credible system/Google serif, keep it light-loading" |

**Serif rationale:** Lora is a well-kerned, German-credible serif with strong Latin-extended coverage and a small payload. It reads as "paper credential" without typographic excess. If executor finds a technical reason to substitute, Merriweather and Playfair Display are acceptable fallbacks in that order.

**Registry:** shadcn not initialized. No third-party registries. Registry safety gate: not applicable.

**No new npm packages beyond Lora (zero runtime cost — it is a Google Font loaded via `next/font/google`, not an npm package).** All other constraints from `CLAUDE.md` "What NOT to Add" remain in force.

## Spacing Scale

Inherited 8-point grid from Phase 1/2. Phase 4 adds three landing-specific tokens.

| Token | Tailwind | Value | Usage |
|-------|----------|-------|-------|
| xs | `gap-1` / `px-1` | 4px | Icon-to-text gaps, button micro-padding (inherited) |
| sm | `gap-2` / `p-2` | 8px | Inline control spacing, nav link gap (inherited) |
| md | `gap-4` / `px-4 py-3` | 16px | Form element internal padding, section gaps (inherited) |
| lg | `gap-6` / `p-4` | 16–24px | Card internal padding, vertical gap inside landing cards (inherited) |
| xl | `py-12 px-6` / `sm:px-12` | 24–48px | Page outer padding (inherited) |
| section | `py-20 sm:py-28` | 80–112px | Vertical breathing room between the six landing sections |
| hero | `pt-24 pb-20 sm:pt-32 sm:pb-28` | 96–128px top, 80–112px bottom | Hero section top/bottom padding |
| content-max | `max-w-4xl mx-auto px-6` | 896px container, 24px side padding | Landing content container (wider than the tool's `max-w-3xl`) |

Exceptions:
- Touch targets: 44px minimum via padding expansion — inherited from Phase 1.
- Nav height: `h-14` (56px) — hairline border-bottom.
- CTA button vertical padding: `py-3` (12px top + bottom) for all CTAs on the landing.
- Before/after mockup fixed height: `h-64` (256px) — see Mockup spec below.
- Hero hairline underline decoration: `border-b-2` on the accent span — 2px, not a full underline.

## Typography

Phase 4 EXTENDS the Phase 1/2 scale (3 sizes, 2 weights) by adding 2 landing-specific sizes and wiring the serif font. The tool UI retains the existing 3-size scale unchanged.

### Complete type scale (landing + tool)

| Role | Family | Size | Tailwind | Weight | Tailwind | Line Height | Usage |
|------|--------|------|----------|--------|----------|-------------|-------|
| Body / field text | Geist Sans | 14px | `text-sm` | 400 | `font-normal` | 1.5 | Tool UI — all field content, notes, placeholders (inherited) |
| Label / meta | Geist Sans | 12px | `text-xs` | 600 | `font-semibold` | 1.4 | Uppercase section labels, landing eyebrow labels (inherited) |
| Heading | Geist Sans | 24px | `text-2xl` | 600 | `font-semibold` | 1.2 | Tool h1, Lebenslauf name display (inherited) |
| CTA / button | Geist Sans | 14px | `text-sm` | 600 | `font-semibold` | — | All buttons, landing + tool (inherited) |
| Section title | **Lora** (serif) | 28px | `text-3xl` | 600 | `font-semibold` | 1.2 | Landing section headings ("Two documents. Both have to survive the scan." etc.) |
| Hero headline | **Lora** (serif) | 40px mobile / 52px desktop | `text-4xl sm:text-5xl` | 700 | `font-bold` | 1.15 | Hero only — "Win the 8-second German recruiter scan." |
| Hero subhead | Geist Sans | 16px | `text-base` | 400 | `font-normal` | 1.6 | Hero subhead — the D-08 bilingual output sentence |
| Body / landing prose | Geist Sans | 16px | `text-base` | 400 | `font-normal` | 1.65 | Landing body paragraphs (how-it-works steps, trust band, founder note) |
| Nav / footer | Geist Sans | 14px | `text-sm` | 600 (nav links) / 400 (footer) | — | 1.4 | Navigation links, footer label |

**Hard constraints:**
- Serif (Lora) is used ONLY on the landing: hero headline + section titles. NEVER on tool UI, buttons, labels, or body paragraphs.
- `font-bold` (700) is permitted ONLY on the hero headline. All other emphasis remains `font-semibold` (600) per Phase 1 contract.
- No `text-lg` on the tool UI. `text-base` (16px) is landing-only.
- The 40/52px hero size pair is landing-only. No other element exceeds `text-3xl` (28px).
- `font-medium` (500) remains prohibited everywhere.

## Color

Phase 4 introduces the deep-blue trust accent and drops dark mode. All `dark:` variants are removed from `globals.css` and from retrofitted components.

### Surface palette (light-only — dark mode removed per D-12)

| Role | Hex | Tailwind | Usage |
|------|-----|----------|-------|
| Dominant surface (60%) | `#ffffff` | `bg-white` | Page background, landing sections, tool content card |
| Secondary surface (30%) | `#f4f4f5` | `bg-zinc-100` | Landing section alternates (trust band, how-it-works), tool elevated cards, before/after mockup background |
| Hairline border | `#e4e4e7` | `border-zinc-200` | All card outlines, section dividers, nav bottom border |
| Text primary | `#18181b` | `text-zinc-900` | All body content, headings, field values |
| Text secondary | `#71717a` | `text-zinc-500` | Muted labels, subtitles, eyebrow text, hero subhead, zero-retention line, trust-band body |
| Text placeholder | `#a1a1aa` | `text-zinc-400` | Textarea placeholders, decorative/optional text only |

**Dark mode removal:** Delete the `@media (prefers-color-scheme: dark)` block in `globals.css`. Remove all `dark:` Tailwind classes from `page.tsx`, `layout.tsx`, and all components under `src/components/`. The tool background becomes `bg-zinc-50` (tool input page) / `bg-white` (tool content card) — matching the existing Phase 1 light values without dark variants.

### Accent system (NEW — D-11)

| Role | Hex | Tailwind | Reserved for (EXACT list — nothing else) |
|------|-----|----------|------------------------------------------|
| Deep-blue trust accent | `#1d4ed8` | `text-blue-700` / `bg-blue-700` / `border-blue-700` | 1. Hero headline hairline underline decoration on "8-second" span; 2. ### B. `globals.css` — light-only cleanup (D-11/D-12)

Required changes — exact delta:

1. Remove the entire `@media (prefers-color-scheme: dark) { :root { ... } }` block.
2. Change `font-family: Arial, Helvetica, sans-serif` on `body` to `font-family: var(--font-geist-sans), system-ui, sans-serif`.

```css
@import "tailwindcss";

:root {
  --background: #ffffff;
  --foreground: #18181b;

  --color-accent: #1d4ed8;
}

@theme inline {
  --color-background: var(--background);
  --color-foreground: var(--foreground);
  --font-sans: var(--font-geist-sans);
  --font-mono: var(--font-geist-mono);
}

body {
  background: var(--background);
```

### H. Motion contract (D-13)

All motion is opt-in only — the default is no motion.

| Element | Animation | Implementation |
|---------|-----------|----------------|
| Landing sections | Quiet fade + 8px slide-up on scroll-into-view | CSS `@keyframes` or Tailwind `animate-fade-in-up` custom animation class. Trigger: `IntersectionObserver` with `threshold: 0.1`. Not applied to the hero (it is the first visible element, no scroll needed). |
| Primary CTA buttons (landing) | Gentle 2px upward lift on hover | `hover:-translate-y-0.5 transition-transform duration-150` — applies to all `bg-blue-700` CTA buttons |
| `prefers-reduced-motion` guard | All animations disabled | `@media (prefers-reduced-motion: reduce) { * { animation: none !important; transition: none !important; } }` — add to `globals.css` |
| Tool UI | No new animations | Existing `animate-pulse` skeleton is already respects reduced motion via Tailwind's built-in safe list |

**Forbidden motion (per D-13):** No parallax, no animated gradient, no particle/aurora/shader backgrounds, no autoplay video, no background animation of any kind on the landing.

**Scroll animation implementation note:** Use `IntersectionObserver` in a custom `useIntersectionObserver` React hook or a small vanilla JS script injected via `<script>` in the landing. Do not install a scroll-animation library (CLAUDE.md "What NOT to Add" principle).

## Accessibility

Phase 4 closes the WCAG-AA gaps flagged in Phase 1 (D-19). This is a full-pass requirement, not aspirational.

### Landing page

| Element | Requirement |
|---------|-------------|
| `<html lang="en">` | Already set — confirm and keep |
| Landmark structure | `<nav>`, `<main>`, `<footer>` — required. Each of the six landing sections should use `<section>` with a descriptive `aria-labelledby` pointing to its `<h2>`. |
| Heading hierarchy | `<h1>` hero headline → `<h2>` section titles → `<h3>` card subheadings. No heading skips. |
| CTA links | All `<a href="/app">` buttons must have visible focus: `focus-visible:outline-2 focus-visible:outline-blue-700 focus-visible:outline-offset-2` |

| Trust band checkmarks | Inline SVG checkmarks: `aria-hidden="true"` — the text label carries the meaning. |
| Hairline underline decoration | The absolute-positioned `border-b-2` span must have `aria-hidden="true"`. |
| Blue accent decorative bar (Section 5) | `aria-hidden="true"`. |
| Scroll animations | `prefers-reduced-motion` disables all animations (see motion contract). Animated elements must still be readable in static state. |
| Color contrast | All text on white: `text-zinc-900` (21:1 AA/AAA), `text-zinc-500` (7.5:1 AA). `text-zinc-400` (3.1:1) is NOT AA — permitted only for decorative/placeholder text. Never use `text-zinc-400` for any text a user must read. |
