<objective>
Add the input-length security guard to the CV-parse slice end-to-end: a server-side 400 on oversized `resumeText` in `/api/parse` (the real cost/abuse boundary), plus a client-side live character counter and disabled submit in `InputView` so users never hit the 400 in normal use. Align the parse route's existing English missing-input message to German. Confirm the parse path introduces no new server-side persistence and never logs rejected content.

Purpose: Make the CV-input step safe to put real (and oversized/abusive) input in front of users — capping Opus input cost and abuse while preserving the zero-retention posture.
Output: A guarded `/api/parse` route and a guarded `InputView` with a working char counter.
</objective>

## Phase Goal

**As a** user pasting my CV into ScanReady, **I want to** be stopped early (with a clear German message and a live character count) when my text is too long, **so that** I never trigger a confusing server error and the tool stays cheap and safe to run.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client → /api/parse | Untrusted `resumeText` crosses from the browser to the Node route, then to the Claude API. Oversized payload is the abuse/cost vector. |
| guard rejection → server logs | A rejected (oversized) `resumeText` could leak into logs if naively logged — a retention violation. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-01 | Denial of Service / cost abuse | `/api/parse` POST handler (oversized `resumeText` → Opus input cost) | mitigate | Server-side `resumeText.length > 30_000` check returns 400 before `anthropic.messages.parse()` is called (Task 1); client counter + disabled submit (Task 2) prevents normal users reaching it. |
| T-03-02 | Information disclosure (retention leak) | Guard rejection path / logging | mitigate | Guard returns early and logs nothing; existing `console.error("parse error", err)` logs only the caught Error object, never `resumeText` (D-05, verified by negative grep in Task 1). |
| T-03-03 | Information disclosure (client persistence) | `InputView` state | accept | `resumeText` lives in React component memory only; no localStorage/sessionStorage introduced (negative grep in Task 2). Consistent with the verified 02-SECURITY.md zero-retention baseline (AR-02-01). |
| T-03-SC | Tampering (supply chain) | npm/pip/cargo installs | mitigate | Zero new packages this plan — no install tasks. Both edits are to existing files using existing imports (`NextResponse` already imported in parse route). |
</threat_model>
