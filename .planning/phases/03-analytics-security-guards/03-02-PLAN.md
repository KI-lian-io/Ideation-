<objective>
Add the input-length security guard to the cover-letter slice end-to-end: server-side 400s on oversized cvText, jobPosting, and any per-answer field in /api/cover-letter (before the Anschreiben stream is created), and align that route's 400 response shape from plain text to JSON error objects to match /api/parse. On the client, add live character counters to the job-posting textarea and each answer textarea in CoverLetterInputView, and disable submit when any field is over its limit. Confirm no new persistence and no logging of rejected content.

Purpose: Make the cover-letter step safe for real (and oversized/abusive) input — capping Opus input cost and abuse on the streaming route while preserving the zero-retention posture.
Output: A guarded /api/cover-letter route (JSON 400 shape) and a guarded CoverLetterInputView with job-posting + per-answer counters.
</objective>

## Phase Goal

**As a** user writing my Anschreiben in ScanReady, **I want to** be stopped early (with clear German messages and live character counts on the job posting and each answer) when any field is too long, **so that** I never trigger a confusing server error mid-generation and the tool stays cheap and safe to run.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client → /api/cover-letter | Untrusted cvText + jobPosting + free-text answers cross from the browser to the Node streaming route, then to the Claude API. Oversized payload is the abuse/cost vector. |
| guard rejection → server logs | A rejected (oversized) cvText/jobPosting/answer could leak into logs if naively logged — a retention violation. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-04 | Denial of Service / cost abuse | `/api/cover-letter` POST handler (oversized cvText/jobPosting/answers → Opus streaming input cost) | mitigate | Server-side `.length` checks (30k/15k/2k) return 400 before `anthropic.messages.stream()` is created (Task 1); client counters + disabled submit (Task 2) prevent normal users reaching them. |
| T-03-05 | Information disclosure (retention leak) | Guard rejection path / logging | mitigate | Guards return early and log nothing; existing `console.error("cover-letter stream error", err)` logs only the caught Error object, never user input (D-05, verified by negative grep in Task 1). |
| T-03-06 | Information disclosure (client persistence) | `CoverLetterInputView` state | accept | jobPosting/answers live in React component memory only; no localStorage/sessionStorage introduced (negative grep in Task 2). Consistent with the verified 02-SECURITY.md zero-retention baseline (AR-02-03). |
| T-03-SC | Tampering (supply chain) | npm/pip/cargo installs | mitigate | Zero new packages this plan — no install tasks. Both edits are to existing files; the only import added (`NextResponse`) already ships with the installed `next` package. |
