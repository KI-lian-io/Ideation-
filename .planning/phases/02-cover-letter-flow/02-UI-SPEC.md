## Spacing Scale

Identical to Phase 1 — 8-point grid, Tailwind v4 utilities. All values are multiples of 4.

| Token | Tailwind | Value | Usage |
|-------|----------|-------|-------|
| xs | `gap-1` / `px-1` | 4px | Icon-to-text gaps, button micro-padding |
| sm | `gap-2` / `p-2` | 8px | Zero-retention line icon gap, inline control spacing |
| md | `gap-4` / `px-4 py-3` | 16px | Form element internal padding (textareas, inputs), section gaps |
| lg | `gap-6` / `p-4` | 16–24px | Card/callout internal padding, result-view vertical gap |
| xl | `py-12 px-6` / `sm:px-12` | 24–48px | Page outer padding (existing in `page.tsx` line 358) |

Exceptions (same as Phase 1):
- Touch-target minimum for action buttons: 24px rendered, 44px tap target via padding expansion.
- Job-posting textarea: `resize-y`, `rows={10}`.
- Personalization question textareas: `resize-y`, `rows={3}` each.
- Post-stream editable letter textarea: `resize-y`, `rows={18}`.

#### `CoverLetterStreaming` — live generation skeleton + token append

Reducer phase: `cover_letter_streaming`.

- Show the `animate-pulse` skeleton blocks (reuse Phase 1 pattern exactly) with status text "Anschreiben wird generiert…" until the first token arrives. Adaptive thinking can delay the first token by several seconds — the skeleton must remain visible for the full pre-token pause.
- Status text: `text-sm text-zinc-400 dark:text-zinc-500` — do not add a percentage or step count.
- Once the first token arrives, replace skeleton with the letter block (below). Continue appending tokens directly into the letter block as they arrive.
- The letter block is **read-only during streaming** — no `EditableField`, no click targets in the letter text. Disable "Regenerieren" and "Start over" during streaming (re-enable on completion).

Skeleton markup (reuse Phase 1 structure):
```
<div role="status" aria-label="Anschreiben wird generiert, bitte warten">
  <div class="animate-pulse space-y-3">
    <div class="h-4 bg-zinc-200 dark:bg-zinc-700 rounded w-3/4" />
    <div class="h-4 bg-zinc-200 dark:bg-zinc-700 rounded w-full" />
    <div class="h-4 bg-zinc-200 dark:bg-zinc-700 rounded w-5/6" />
    <div class="h-4 bg-zinc-200 dark:bg-zinc-700 rounded w-2/3" />
  </div>
  <p class="mt-3 text-sm text-zinc-400 dark:text-zinc-500">
    Anschreiben wird generiert…
  </p>
</div>
```

#### `CoverLetterResult` — finished letter block + actions

Reducer phase: `cover_letter_result`.

Layout sketch (from CONTEXT.md `<specifics>`):
```
── Anschreiben ──────────────────────────────────
<letter content — editable via EditableField or textarea>
─────────────────────────────────────────────────
⚠ Trust callout
[ Anschreiben kopieren ] [ .txt herunterladen ]  [ Regenerieren ] [ Start over ]
```

Detailed spec:

**Letter block:**
- Container: `rounded-lg border border-zinc-200 dark:border-zinc-700 bg-zinc-50 dark:bg-zinc-900 px-4 py-4 mt-4`
- Section label above: `text-xs font-semibold uppercase tracking-widest text-zinc-400 mb-2` — "Anschreiben"
- During streaming: plain `<pre class="whitespace-pre-wrap text-sm font-normal text-zinc-900 dark:text-zinc-50 leading-relaxed">` — raw text node only, tokens appended directly. No `dangerouslySetInnerHTML`.
- After streaming (D-06): replace `<pre>` with a `<textarea>` (or `EditableField multiline`) so the user can tweak the voice. Class: same textarea style as the question fields. `rows={18}`. No blue border at rest — blue bottom border only when focused (matches `EditableField` contract).
- "Click to edit" affordance hint (shown once on result): `text-sm text-zinc-400 cursor-pointer` inline note "Klicken zum Bearbeiten" fades in on first render, then disappears after first click. Implement as local `useState` one-shot dismiss.

**Trust callout (D-09 — distinct block, not inline in letter):**
- Container: `mt-4 rounded-lg border border-zinc-200 bg-zinc-100 px-4 py-3 dark:border-zinc-700 dark:bg-zinc-800`
- Label: `text-xs font-semibold uppercase tracking-widest text-zinc-400 mb-1` — "Hinweis"
- Body: `text-sm text-zinc-600 dark:text-zinc-400`
- Copy: "Bitte lassen Sie dieses Anschreiben von einem Muttersprachler prüfen, bevor Sie es absenden."

**Action row:**
```
[ Anschreiben kopieren ] [ .txt herunterladen ] [ Regenerieren ] [ Start over ]
```

- All buttons are `<button>` elements. Flexbox row, `gap-3`, wraps on mobile.
- "Anschreiben kopieren" — primary: `bg-zinc-900 text-white hover:bg-zinc-700 ...` same as Phase 1 CTA. Copy state: "Kopiert ✓" for 1500ms. Error: "Kopieren fehlgeschlagen — bitte manuell auswählen." for 3000ms. Implement with local `useState` (not in reducer).
- ".txt herunterladen" — secondary: `rounded-lg border border-zinc-200 dark:border-zinc-700 bg-white dark:bg-zinc-900 px-4 py-2 text-sm font-semibold text-zinc-700 dark:text-zinc-300 hover:bg-zinc-50 dark:hover:bg-zinc-800`. Triggers browser `<a download>` with `Blob` of the letter text — no server round-trip.
- "Regenerieren" — secondary (same style as .txt button). Dispatches `COVER_LETTER_REGENERATE` (re-POSTs same `cvText + jobPosting + answers`). Disabled during streaming.
- "Start over" — text-style link: `text-sm text-zinc-500 hover:text-zinc-700 cursor-pointer underline-offset-2 hover:underline`. Dispatches `RESET` → returns to `initialState`. No confirmation (D-06 inherits Phase 1 D-16: stateless, nothing is at risk).

**Stream error state:**
If `response.body.getReader()` throws or the stream closes with an error, show the Phase 1 `ErrorView` pattern: red callout box + "Try again" button. "Try again" re-triggers the cover-letter POST with the same inputs (same action as "Regenerieren"). The inputs (job posting + answers) must remain in reducer state during the streaming phase so retry is lossless.

#### Reused from Phase 1 (unchanged)

- `EditableField` — post-stream editable letter (D-06). No API changes. `multiline={true}`.
- Copy-button local state pattern ("Kopiert ✓" / error copy) — apply identical to the Anschreiben copy button.
- `animate-pulse` skeleton — reused verbatim for "Generating…" state (D-05).
- "Start over" → `RESET` dispatch — same action, same behavior.

## States and Interaction Contracts

Phase 2 extends the Phase 1 `AppPhase` union. New phases:

| Phase | Trigger | Visual indicator | Interaction allowed |
|-------|---------|-----------------|---------------------|
| `result` (Phase 1) | Parse success | Lebenslauf editor + "Write Anschreiben" CTA | All editor mutations; clicking "Write Anschreiben" advances to `cover_letter_input` |
| `cover_letter_input` | "Write Anschreiben" CTA clicked | Job-posting textarea + 5 question textareas + disabled-until-filled CTA | Text entry in all fields; "Anschreiben generieren" enabled once job posting non-empty |
| `cover_letter_streaming` | "Anschreiben generieren" submitted | Skeleton (pre-token) → live letter block (post-first-token) | None — all buttons disabled during stream |
| `cover_letter_result` | Stream `done: true` | Finished letter block + trust callout + action row | Copy, download, edit (click-to-edit), Regenerieren, Start over |
| `cover_letter_error` | Stream fetch/read error | Red callout box + "Try again" button | Retry (re-runs POST with same inputs), Start over |

**"Write Anschreiben" CTA placement (result state):**
- Rendered below the `NormGapPanel`, after `mt-8 border-t border-zinc-100 dark:border-zinc-800 pt-6`.
- Style: primary button — same `bg-zinc-900 text-white` contract as all Phase 1 primary buttons.
- Label: "Anschreiben schreiben"
- `aria-label="Anschreiben schreiben"`

**Reducer phase name contract:**
The planner picks exact action names; this spec declares the phases. The four new phases in `AppPhase` are: `cover_letter_input`, `cover_letter_streaming`, `cover_letter_result`, `cover_letter_error`. `RESET` always returns to `input` (Phase 1 `initialState`).

### Interaction contracts: streaming consumer

- Consume `POST /api/cover-letter` response body via `response.body.getReader()` (LOCKED — CL-03, not EventSource).
- Decoder: `TextDecoder` to `string`, append to a `useState` letter buffer.
- Pre-token pause: hold skeleton until the first non-empty text chunk. Thinking blocks are already filtered server-side (`thinking_delta` excluded in `route.ts`) — a multi-second pre-token pause is expected and normal; do not add a timeout fallback in Phase 2.
- On `done: true` from reader: dispatch `COVER_LETTER_DONE` (or equivalent) — transitions to `cover_letter_result`.
- On reader error: dispatch `COVER_LETTER_ERROR` — transitions to `cover_letter_error`.

### Interaction contracts: .txt download

```
const blob = new Blob([letterText], { type: 'text/plain;charset=utf-8' })
const url = URL.createObjectURL(blob)
const a = document.createElement('a')
a.href = url
a.download = 'anschreiben.txt'
a.click()
URL.revokeObjectURL(url)
```

Filename: `anschreiben.txt` (locked — per CONTEXT.md discretion decision).

### Interaction contracts: Regenerate

- Re-uses the same `jobPosting` + `answers` stored in reducer state from the `cover_letter_input` phase.
- Does NOT re-read the Lebenslauf state — uses the same `cvText` snapshot already passed in the first generation (the `toPlainText` output from when the user clicked "Anschreiben schreiben").
- Transitions: `cover_letter_result` → `cover_letter_streaming` (same pre-token skeleton).

**Destructive actions in Phase 2:**
- "Start over" — no confirmation dialog (D-06 / Phase 1 D-16: stateless, nothing persisted). User dispatches `RESET` with a single click.
- "Regenerieren" — no confirmation. Overwrites the current streamed letter with a new generation. The previous letter is lost. This is acceptable because (a) the user can copy first, (b) it is not a data-loss event in the GDPR sense (stateless), and (c) the copy button is visually prominent above it.
