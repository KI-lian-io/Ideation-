<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client -> /api/pass/* | Untrusted request; must prove same-origin, rate limit, session, and PI ownership before minting or crediting |
| client -> /api/humanize, /api/paket/verify | Anonymous PI path plus a new signed-in pass path share these routes |
| route -> service-role write | Pass row write bypasses RLS via the service-role client and must be constrained to the verified caller |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-07-03-01 | Spoofing | /api/pass/intent | mitigate | Require getUser() session before minting; 401 otherwise; same-origin + rate-limit guards run first (mirrors intent rails) |
| T-07-03-02 | Elevation of privilege | /api/pass/verify cross-user credit | mitigate | Require pi.metadata.user_id === session user.id before writing the pass row; a PI for another user is rejected 402 |
| T-07-03-03 | Tampering (replay) | duplicate pass row from replayed PI | mitigate | Idempotent insert on the stripe_payment_intent_id unique constraint (`on conflict do nothing`) |
| T-07-03-04 | Elevation of privilege | expired/forged pass grants fulfillment | mitigate | Entitlement flows through checkPassEntitlement (expires_at > now) reading an RLS-scoped getActivePass row; expired or absent -> no grant |
| T-07-03-05 | Tampering | anonymous rail regression | mitigate | Pass branch is strictly additive; git diff proves paket/intent and humanizer/intent untouched and the PI-first logic unmodified |
| T-07-03-06 | Repudiation | pass fulfillment double-spend | mitigate | Pass grant never marks a PI consumed; the storage/limit ceiling stays enforced by the DB trigger (25) not by client claims |
</threat_model>
