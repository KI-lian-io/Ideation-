<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| authenticated client -> application_packages | Gallery reads/mutates only the caller's rows under RLS |
| read-only display state -> edit controls | UI must not surface controls RLS would silently no-op |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-07-05-01 | Information disclosure | listPackages in the gallery | mitigate | listPackages runs under RLS select-own; a user only ever sees their own packages; no photo field is read or rendered |
| T-07-05-02 | Elevation of privilege | rename on a read-only row | mitigate | Rename control is hidden on read_only rows (not disabled); RLS remains the real enforcement, the UI never presents a dead control |
| T-07-05-03 | Tampering | duplicate-and-tailor bypassing the limit | mitigate | The duplicate is only persisted on explicit save, which passes through the enforce_package_limit trigger like any insert |
| T-07-05-04 | Repudiation | accidental delete | mitigate | Delete keeps the window.confirm gate before deletePackage |
</threat_model>
