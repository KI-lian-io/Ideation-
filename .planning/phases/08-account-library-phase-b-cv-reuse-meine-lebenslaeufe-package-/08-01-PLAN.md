<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| authenticated client -> set_package_status RPC | A signed-in user calls the RPC over /rest/v1/rpc; the package_id argument is untrusted |
| Postgres cascade / FK actions -> application_packages | ON DELETE SET NULL and account-deletion cascades fire implicit UPDATEs/DELETEs that constraints validate |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-08-01 | Elevation of Privilege | set_package_status RPC | mitigate | Function checks `user_id = auth.uid()` inside the body (never a client-supplied id); a caller can only touch their own rows. RLS-independent ownership guard, same pattern as delete_own_account. |
| T-08-02 | Tampering | set_package_status RPC | mitigate | Function updates ONLY the status column and validates new_status against the five keys (raise 'invalid_status' otherwise); it cannot be used to write any other column or to weaken read_only on document content. |
| T-08-03 | Elevation of Privilege | set_package_status grant surface | mitigate | `revoke all from public, anon` + `grant execute to authenticated`; the RPC is not reachable anonymously, and the advisor check in Task 2 confirms no cross-user exposure. |
| T-08-04 | Denial of Service | account deletion after FK change | mitigate | cv_id FK is ON DELETE SET NULL and the status CHECK is null-tolerant, so the implicit UPDATE + cascade during delete_own_account cannot abort (the explicit 0002/0003 lesson); Task 2 probes account deletion still works. |
| T-08-05 | Tampering | subscriptions.cancel_at_period_end | accept | Column has no client write policy (subscriptions has only select_own); it is written solely by the webhook via the service role, same trust model as status/current_period_end. |
</threat_model>
