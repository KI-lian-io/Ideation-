<objective>
Deliver surface 08's per-package status chip: a quiet mono-label chip (Entwurf / Beworben / Interview / Absage / Zusage) on every package card in both galleries, editable via a dropdown that never cycles, safe on read-only rows because all writes go through the ownership-checked `set_package_status` RPC (migration 0004). On the first PDF export or copy of a saved package, status auto-suggests "beworben" as an inline undoable nudge.

Purpose: high-volume applicants want a lightweight sense of where each application stands, without a kanban tracker (an explicit PRD non-goal). This is one column, one dropdown, no board. The read-only exception is deliberate: status is package METADATA, not document content, so it survives the write lock, enforced by the RPC's ownership-only check rather than by weakening the read-only contract.
Output: a `StatusChip` primitive, the `setPackageStatus` caller, status.* copy, the chip in both galleries with status-aware filtering, and the auto-suggest with inline undo.
</objective>

## Phase Goal (user story)

**As a** signed-in job seeker tracking many applications, **I want to** mark each saved application's status (draft, applied, interview, rejected, offer) from its card, **so that** I see at a glance where each one stands, without a heavyweight tracker. (Derived from PRD 6.4 / non-goal 3.1 and the 08 design deck; status auto-suggests "applied" the first time I export or copy.)

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| authenticated client -> set_package_status RPC | The chip's onSelect and the auto-suggest both call the RPC with a package_id + status |
| read-only document contract | Status must be writable on read_only rows WITHOUT reopening document-content edits |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-08-13 | Elevation of Privilege | set_package_status via StatusChip | mitigate | The RPC (0004) checks user_id = auth.uid() server-side and updates ONLY status; the client cannot flip another user's status or any other column, regardless of what the chip sends. |
| T-08-14 | Tampering | read-only exception | mitigate | Status writes bypass the RLS read_only-blocked plain UPDATE by design, but the RPC still validates the status value against the five keys and touches no document column, so the read-only document contract is intact; the exception is commented at every render site. |
| T-08-15 | Tampering | status filter (client-side) | accept | The filter is a substring match over already-fetched, RLS-scoped rows and the i18n label map; no query is built from user input, so no injection surface. |
| T-08-16 | Spoofing | auto-suggest for anonymous | mitigate | suggestBeworben no-ops unless savedPackageId is set, which only happens after a signed-in save; anonymous users never trigger a write. |
</threat_model>
