<objective>
Deliver surface 09's Plus subscription lifecycle on /konto: the cancelled-but-running state (paid-until date + "Kuendigung zuruecknehmen"), the expired state (neutral downgrade explainer), and a new un-cancel route that flips Stripe's cancel_at_period_end back to false. Plus remains "Geplant" and non-buyable everywhere; the renewal-reminder email is explicitly NOT built.

Purpose: the honest-subscription position (anti-Abofalle) needs the full lifecycle visible and reversible: a user who cancels can see exactly when it ends, that nothing more is charged, that nothing is deleted, and can undo the cancellation. This mirrors the existing cancel route's guard/auth shape. The subscriptions table has no client write policy, so the durable row sync is the webhook (service role); the routes only talk to Stripe (same dual-write model the cancel route already relies on).
Output: cancel_at_period_end plumbed through subscription.ts + the webhook, a new reactivate route, the two new /konto card states, plus.* copy, and a founder-gate note for the reminder email.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| authenticated client -> /api/subscription/reactivate | A signed-in user asks to un-cancel; the route must only touch that user's own subscription |
| Stripe -> /api/stripe/webhook | Cross-origin webhook; the HMAC signature is the authentication (unchanged) |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-08-17 | Elevation of Privilege | /api/subscription/reactivate | mitigate | Auth required (401 without a session); the subscriptions select is RLS-scoped (subscriptions_select_own), so a caller can only enumerate and reactivate their OWN subscription ids passed to Stripe. |
| T-08-18 | Spoofing/CSRF | /api/subscription/reactivate | mitigate | enforceSameOrigin + enforceRateLimit("intent") applied first, identical to cancel/route.ts, so cross-origin and abusive calls are blocked before any Stripe work. |
| T-08-19 | Tampering | reactivate scope | mitigate | Only rows matching `isActiveStatus(status) && cancel_at_period_end` are updated; a non-cancelling or inactive subscription yields 404, so the route cannot resurrect an already-ended subscription or alter status. |
| T-08-20 | Tampering | webhook cancel_at_period_end sync | mitigate | The webhook keeps its constructEvent HMAC check (STRIPE_WEBHOOK_SECRET) and writes via the service role; adding cancel_at_period_end to the upsert changes no auth or control flow. |
| T-08-21 | Repudiation | un-cancel intent | accept | Stripe is the source of truth and records the update; the /konto row reflects it once the webhook fires (same durable-sync model as cancel), so state is reconstructable from Stripe. |
</threat_model>
